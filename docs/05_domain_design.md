# ドメイン設計書

## エンティティ

| エンティティ    | 説明                                       | 主な属性（プロパティ）                                                                                              |
| --------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| FoodItem        | 冷蔵庫内で管理する食材1件                  | id, name, status, image, bestBeforeDate, purchasedAt, price, memo, storeId, storageLocationId, createdAt, updatedAt |
| Store           | 食材の購入先として記録するスーパー         | id, name, createdAt, updatedAt                                                                                      |
| StorageLocation | 食材の保存場所（冷蔵／冷凍／常温／追加分） | id, name, kind, createdAt, updatedAt                                                                                |

> ※ Account は認証・インフラの関心事のため、本ドメイン設計からは除外
>
> ※ FoodStatus は Entity ではなく VO として扱う（下記参照）

---

## VO（Value Object）

| 名前           | 使う場所                | 守るルール（ほんの少しの約束）     | 例         | 備考                                  |
| -------------- | ----------------------- | ---------------------------------- | ---------- | ------------------------------------- |
| FoodName       | FoodItem.name           | 空NG／前後空白トリム               | 卵         | 食材名は必須で意味が強いためVOにする  |
| FoodStatus     | FoodItem.status         | 未消費 / 消費中 / 消費 / 廃棄 のみ | 未消費     | 食材の状態はアプリの意味が強い        |
| BestBeforeDate | FoodItem.bestBeforeDate | 日付として正しい                   | 2026-01-31 | 任意（NULL可）                        |
| PurchasedAt    | FoodItem.purchasedAt    | 日付として正しい                   | 2026-01-23 | 任意（NULL可）                        |
| LocationKind   | StorageLocation.kind    | default / custom のみ              | default    | 固定3種かユーザー追加かを判定するため |

## 集約

| **🏷️ チーム名（集約）**                       | **👑 集約ルート（リーダー）**                                         | **👥 中にいるメンバー（子エンティティ・VO）**                               | **🔗 外との関係・使い方** | **💬 チームの役割（ざっくり）**                     |
| --------------------------------------------- | --------------------------------------------------------------------- | --------------------------------------------------------------------------- | ------------------------- | --------------------------------------------------- |
| 🧊 **FoodItemチーム**                         | **FoodItem**                                                          | - FoodName（VO）- FoodStatus（VO）- BestBeforeDate（VO）- PurchasedAt（VO） | - Store を参照（storeId） |
| - StorageLocation を参照（storageLocationId） | 冷蔵庫内の食材1件を管理するチーム。状態・期限・購入情報をまとめて扱う |
| 🏪 **Storeチーム**                            | **Store**                                                             | なし                                                                        | - FoodItem から参照される | 食材の購入先となるスーパーを管理するマスタチーム    |
| 📦 **StorageLocationチーム**                  | **StorageLocation**                                                   | - LocationKind（VO）                                                        | - FoodItem から参照される | 保存場所を管理するチーム。固定3種の制約をここで守る |
| ⚪ **共通VO**                                 | なし（単独）                                                          | - FoodName                                                                  |

- FoodStatus
- LocationKind | 各チームで使われる共通ルール | |

## ドメインロジック

### 🧊 FoodItemチーム（食材の世界）

| **🧩 ルール**                        | **💬 なにをしてる？**                    |
| ------------------------------------ | ---------------------------------------- |
| 食材名は必須                         | 空だと何の食材かわからなくなるため       |
| 食材の状態は4種類のみ                | 未消費 / 消費中 / 消費 / 廃棄 に限定する |
| 状態変更は FoodItem が責任を持つ     | 状態遷移のルールを外に散らさない         |
| 保存場所の変更は FoodItem 経由で行う | 食材がどこにあるかを一貫して管理する     |
| 賞味期限は任意                       | 入力負荷を下げるため                     |
| 購入情報（店・日付・価格）は任意     | MVPでは最低限の記録に留める              |

---

### 🏪 Storeチーム（スーパーの世界）

| **🧩 ルール**  | **💬 なにをしてる？**           |
| -------------- | ------------------------------- |
| 店名は自由入力 | 統一ルールは設けない（MVP方針） |

---

### 📦 StorageLocationチーム（保存場所の世界）

| **🧩 ルール**                         | **💬 なにをしてる？**                          |
| ------------------------------------- | ---------------------------------------------- |
| 固定3種（冷蔵／冷凍／常温）は削除不可 | 保存場所が消えて食材が参照不能になる事故を防ぐ |
| 固定3種は種別（kind=default）で判定   | ロジックを名前に依存させない                   |

---

### ⚪ 共通ルール（どのチームでも同じ）

| **🧩 ルール**                  | **💬 なにをしてる？**                          |
| ------------------------------ | ---------------------------------------------- |
| 集約はそれぞれ独立して管理する | 他チームの内部状態を直接変更しない             |
| 参照関係はIDで持つ             | 親子関係にしないことでライフサイクルを分離する |

## 集約境界とトランザクション境界

### 集約とトランザクションの関係

このシステムでは、**集約（Aggregate）の境界 = トランザクション境界**とします。

| 集約            | トランザクション対象 | 理由                                          |
| --------------- | -------------------- | --------------------------------------------- |
| FoodItem        | foodItem             | 食材1件の状態・期限・購入情報は一体で管理する |
| Store           | store                | 単一エンティティで完結                        |
| StorageLocation | storageLocation      | 単一エンティティで完結                        |

---

### トランザクションが必要な操作

1. **集約の作成**
   - FoodItem 作成
   - Store 作成
   - StorageLocation 作成
2. **集約の更新**
   - FoodItem 更新（状態変更・保存場所変更・購入情報更新など）
   - Store 更新
   - StorageLocation 更新
3. **集約の削除**
   - FoodItem 削除
   - Store 削除
   - StorageLocation 削除（※固定3種を除く）

---

### トランザクション不要な操作

1. **読み取り専用のクエリ**
   - FoodItem 一覧取得
   - Store 一覧取得
   - StorageLocation 一覧取得
