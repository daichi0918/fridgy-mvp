## 🏗️ 背景

日常の買い物・自炊では、「冷蔵庫に何があるか」「いつまで使えるか」を思い出せず、重複購入や賞味期限切れが発生しやすい。

また、スーパーごとに価格が異なるため「どの店でいくらで買ったか」を記録していないと、購入判断が感覚的になり、比較や再利用ができない。

これらはユーザーの記憶力の問題ではなく、在庫・賞味期限・購入価格の情報が分散し、必要な瞬間に参照できないという構造的な問題である。

---

## ❗ 課題

- 冷蔵庫内の在庫を把握できず、重複購入や買い忘れが起きる
- 賞味期限が近い食材を見落とし、期限切れ・廃棄が発生する
- スーパーごとの価格情報が残らず、価格判断が再利用できない

---

## 🎯 目的

- 冷蔵庫内の食材について、以下を1箇所で参照できる状態を作る
  - 冷蔵庫に何があるか（在庫）
  - それがいつまで使えるか（賞味期限）
  - どの店でいくらで買ったか（スーパーと価格）
- これにより、買い物時に「買うべきか」を判断するための材料を即座に確認でき、重複購入・期限切れを減らす意思決定を可能にする

---

## ⚙️ 機能要件（MVP版）

### 🧊 食材管理

- 食材を登録できる（手入力）
  - **必須**：食材名
  - **任意**：
    - 画像
    - 賞味期限（日付）
    - 購入日
    - 購入スーパー
    - 価格
    - 保存場所
    - メモ
    - カテゴリ（将来拡張）
- 食材を一覧表示できる
  - デフォルト：追加順
  - 並び替え：賞味期限が近い順 / 購入日が新しい順
- 食材の詳細を閲覧できる
- 食材を編集・削除できる（物理削除）
- 食材の状態を変更できる
  - 状態：未消費 / 消費 / 消費中 / 廃棄

### 🔍 検索

- 食材を検索できる（食材名の部分一致）

### 🏪 店舗管理

- スーパーをCRUDできる
  - 店名は自由入力（統一ルールは設けない）
- スーパー一覧を表示できる
- 食材登録時にスーパーを選択できる（候補から選択＋必要なら追加）

### 📦 保存場所管理

- 保存場所をCRUDできる（例：野菜室、チルド、パントリー等）
- 初期状態で以下の保存場所が存在する
  - 冷蔵 / 冷凍 / 常温
- **上記3つは削除・名称変更不可（固定）**
  - 理由：MVPで「保存場所が消えて食材が参照できない」などの事故を防ぐため

### 💰 価格記録

- 食材ごとに「購入価格」を1つ記録できる（自由入力）
- 表示は「店名＋価格」が確認できればOK

---

## 🌱 将来の拡張予定

### 🔔 賞味期限通知

- 賞味期限が近い食材を通知する（例：3日前 / 前日）
- 通知手段は将来検討（Web Push / メール等）

### ⚖️ 価格の高度化

- 100gあたり等の単位価格、量の記録
- 同一食材の購入履歴（最安・平均などの統計）

### 🔎 検索・フィルタ強化

- 保存場所別、期限までの日数、スーパー別、状態別などのフィルタ
- メモ全文検索

### 🧾 レシート画像からの自動取得

- レシート画像から以下を抽出し、入力負荷を下げる
  - スーパー名
  - 価格（可能なら品目も）
- 抽出結果の手動修正（補正）を可能にする

---

## 🔐 非機能要件（MVP）

- **認証**：Googleログイン／ログアウト／初回登録（OAuth2）
- **データベース**：Postgres（Neon想定）
- **検索**：食材名の部分一致
- **UI**：Web（スマホ優先）、将来PC対応可能な構造
- **パフォーマンス**：軽量シングルユーザー規模を想定
- **デプロイ**：Cloud Run + Cloud Build
- **CI/CD**：GitHub Actions
- **監視**：Cloud Loggingのみ（最低限）
